Local Computation

Each simulated node integrates only its assigned sub-interval, independently and locally, before anything leaves the node.

🧩

Data Integrity

Every node result is hashed with SHA-256 into an immutable block, chained to the block before it.

🛡️

Protected Results

Only the aggregated, hashed result is recorded on the ledger — raw intermediate data is never persisted beyond the node.

🔍

Blockchain Verification

Anyone can recompute the chain of hashes to confirm no block was altered after the fact.

Note: SecureSum is an academic simulation demonstrating the principles of privacy-preserving distributed computation and blockchain-style integrity verification. It is not a production-grade privacy or cryptocurrency system.

About SecureSum

Simulation Framework for Privacy-Preserving Distributed Numerical Integration Using Blockchain

Objective

Demonstrate how numerical integration can be performed across simulated distributed nodes while recording verifiable, tamper-evident results using SHA-256 hash chaining.

Numerical Methods

Implements the Trapezoidal Rule, Simpson's 1/3 Rule, Simpson's 3/8 Rule, and the Midpoint Rule, each computed with NumPy and compared against SymPy's exact symbolic integral where available.

Distributed Computation

The integration interval is split evenly across simulated nodes, each computing its own local result independently before aggregation.

Privacy

Node computations stay local; only hashed, aggregated results are recorded — illustrating the shape of a privacy-preserving pipeline.

Blockchain Simulation

Each node's contribution becomes a SHA-256-hashed block, linked to the previous block's hash, verifiable at any time via the Blockchain page.

Technologies Used

Flask, NumPy, SymPy, SQLite, Chart.js, and Python's hashlib — kept intentionally simple for an academic project.
